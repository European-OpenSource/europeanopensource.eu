# AGENTS.md block

`cli.sh` writes a managed block into the consumer's `AGENTS.md`, between the markers
`<!-- [walle:START] -->` and `<!-- [walle:END] -->`. If `AGENTS.md` does not exist it is created;
if it exists, only the block is replaced and the rest of the file is kept.

## What the block contains

The block is built from `walle/ai/agents.block.md` plus a list generated from the manifest:

- the rule that `@walle/` paths are read-only and the list of consumer zones;
- where configuration lives, that it is validated at build time, and what `theme.json` holds;
- the styling contract: site CSS in `@layer site`, public custom properties, the `site` variant,
  and what is unsupported (inner classes, `!important`, repeated selectors);
- the component model: variants, boolean modifiers, embedded component replacement through
  `app.json` `components`, and importing an original by file path when wrapping it;
- language and `labels`;
- the optional features and the rule that walle injects their routes;
- the update commands;
- **Active walle modules**: one line per active module with its purpose and its managed and seed
  paths, generated by the CLI so it always matches the project.

## Updating the block

The block is regenerated on every `just walle-update` and `cli.sh add`. Do not edit it by hand;
add project-specific instructions to `AGENTS.md` outside the markers. The `12_ai_harness.sh` e2e
scenario checks that the block lists only active modules and that content outside the markers
survives an update.
